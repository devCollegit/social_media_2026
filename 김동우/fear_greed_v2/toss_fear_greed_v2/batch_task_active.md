# 추가 판정 작업 지시 (A6 헷갈리는 글, A7 재판정 공통)

류창민 `batch_task.md`와 같은 절차입니다. 판정 기준은 그대로 `label_guide.md`를 씁니다.

묶음 이름을 `<B>`라고 할 때 (예: b40):

1. 판정 기준을 먼저 끝까지 읽으세요: label_guide.md
2. 판정할 글: batches/<B>.jsonl (한 줄에 글 하나, 최대 1,000줄). 필드: id, stock_name, is_reply, execution_side, text, parent_text.
3. 결과 파일: labels/<B>.jsonl — 한 줄에 {"id": "...", "label": "greed|fear|neutral|irrelevant|unsure"}. 입력의 모든 id를 빠짐없이, 입력 순서대로.

진행 방법
- 결과 파일이 이미 있으면 지우고 새로 시작하세요.
- 입력을 125줄씩 나눠 읽고, 125건 판정이 끝날 때마다 결과 파일 끝에 덧붙이세요.
- 다 쓰고 나서 줄 수가 입력 줄 수와 같은지 확인하세요. 다르면 빠진 id를 찾아 채우세요.
- 끝나면 `python3 check_batch.py <B>`로 검사하세요.

이 묶음은 분류 모델이 헷갈려 한 글을 일부러 모은 것입니다. 평소보다 애매한 글이 많습니다.
- 그래도 기준표의 규칙대로 판정하세요. 애매하면 unsure입니다.
- 모델의 예측은 묶음에 들어 있지 않습니다. 추측하려 하지 마세요.

재판정(A7)일 때
- 같은 묶음을 처음 판정한 결과(labels/)를 보지 마세요. 결과는 labels_recheck/<B>.jsonl에 쓰세요.
- 상위 모델로 갈린 글만 다시 볼 때는 adjudicate.jsonl을 입력으로, labels_adjudicated/에 같은 형식으로 쓰세요.

규칙
- 판정은 글을 직접 읽고 하세요. 키워드 스크립트 등으로 자동 분류하지 마세요.
- 위 경로 밖의 파일은 만들거나 고치지 마세요. 인터넷·외부 API 금지.
- 보고에 원문을 옮기지 마세요. 줄 수와 라벨별 개수만 한 줄로 보고하세요.
