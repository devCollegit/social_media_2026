# 저비용 LLM 파일럿과 병렬 후속 작업 결과

2026-10-21, 사용자 요청으로 gpt-6-luna 에이전트를 사용했다.
추가 사람 검수는 보류 상태를 유지했다. 사람 답안·기존 예측은 분류 에이전트에 제공하지 않았다.
API 키를 읽거나 별도 API 수집기를 사용하지 않고 현재 세션의 에이전트 기능으로 실행했다.
정확한 토큰 사용량·실제 비용·temperature·API 모델 ID는 확인되지 않았으며 추정하지 않는다.

| 결과 검증 | ID 누락·중복, 허용 판정, 근거 인용과 부모 사용 여부 검증 도구 |

## 파일럿 결과

| 감정 판정 | 건수 |
| --- | --- |
| 긍정 | 45 |
| 중립 | 22 |
| 부정 | 89 |
| 혼합 | 10 |
| 판단유보 | 134 |

관련성은 관련 211건, 무관 50건, 관련 불명 39건이었다.
관련인 글 안에서도 45건은 감정을 유보했고 10건은 혼합이었다.
따라서 감성 점수에 쓸 수 있는 3방향 판정은 **156/300건(52%)**이다.
무관·불명·유보를 중립으로 채우지 않았다.

### 같은 156건에서 비교

| 지표 | 저비용 LLM | 기존 사전 |
| --- | --- | --- |
| 사람과 같은 판정 | 94/156, 60.3% | 67/156, 42.9% |
| Macro-F1 | 0.5500 | 0.3331 |

사람 판단도 불확실한 단독 검수 기준이며 객관적 정답이 아니다.
LLM이 선택한 일부 표본의 조건부 비교이므로 전체 300건의 기존 사전 58%와 직접 비교하면 안 된다.
전체 300건 중 LLM이 3방향으로 답하고 사람과 같은 것은 94건(31.3%)이다.
나머지를 모두 오답이라고 해석하지 않고 유보·혼합 및 불일치를 분리한다.
특히 사람 중립 대비 LLM 중립 재현율은 해당 부분집합에서 24.7%로 낮아,
LLM이 감정을 지나치게 방향성 있게 해석하는 경우도 검토해야 한다.
근거가 원문에 존재한다는 형식 검증은 그 근거로 해석이 옳다는 검증이 아니다.

## 실행 간 일관성 점검

같은 30개 글을 다른 gpt-6-luna 에이전트가 기존 결과를 보지 않고 다시 판단했다.

- 감정 판정 일치: 24/30건, 80%
- 관련성 판정 일치: 24/30건, 80%
- 관련성과 감정이 모두 일치: 21/30건, 70%

같은 판단 기준을 전달했지만 완전히 동일한 프롬프트 바이트·난수 설정을 통제한 실험은 아니다.
표본도 30건뿐이므로 모델 자체의 정확한 재현성 비율로 일반화하지 않는다.
반복 출력에는 context_status라는 추가 필드가 있어 원본을 보존하고 그 키만 제거한 별도 파일을 검사했다.
판정·근거는 수정하지 않았으며 구조 정규화 전후 SHA를 기록했다.

## 준비된 도구와 입력

- `analysis/llm_results.py`: 모델 JSONL 형식·ID·인용 검증 및 조건부 사람 일치율 비교
- `integration/prepare_llm_input.py`: 전체 입력을 whitelist 필드와 SHA가 있는 묶음으로 준비
- `analysis/llm_daily.py`: 15:30 종가 경계와 다음 거래일 배정을 유지하며 분모·제외 수와 지수를 별도 집계

실제 결과는 Git 제외 경로에 있다.

| 경로 | 내용 |
| --- | --- |
| state/llm_luna_pilot_20261021 | 300건 판정, 지시문, manifest, 평가 결과 |
| state/llm_luna_repeat_20261021 | 반복 30건 원본·정규화 결과·비교 |
| data/llm_input_20261021 | 전체 7,632건 입력만 준비, 255묶음 |

일별 집계는 파일럿 300건으로 연결 점검만 했다.
전체 중 일부만 처리할 때는 --allow-partial을 명시해야 하며 날짜별 미분류 수를 남긴다.
7,632건 전체의 LLM 판정·LLM 감성지수 연구 분석이 완료된 것은 아니다.
이 파일럿 일별 결과를 게시판 전체 분위기나 주가 예측 결과로 해석하지 않는다.

## 다음 우선순위

1. 사람 라벨을 추가하지 않고, 동일 프롬프트·고정된 실행 설정으로 반복 비교 가능한 실행 방식을 정한다.
2. 현재 48%의 유보·혼합과 실행 간 차이를 숨기지 않고 기록한다. 유보를 줄이기 위해 답을 강요하지 않는다.
3. 전체 분류를 실행할 때에는 묶음별 누락·중복 검증과 ID 기반 재개, 사용량 기록을 적용한다.
4. 전체 판정이 끝나면 기존 결과를 덮어쓰지 않고 새 지수로 비교한다. 주가 결과를 보고 프롬프트를 고르지 않는다.

새 도구를 포함해 전체 자동 테스트 **90 passed**.
