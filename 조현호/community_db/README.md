# 4종목 커뮤니티 공유 DB

기존에 공유 검사된 자료를 SQLite 하나로 묶었습니다. **새 수집·새 AI 판정은 실행하지 않았습니다.** 파일을 내려받아 각 팀원이 독립적으로 조회하는 스냅샷이며, 여러 사람이 동시에 갱신하는 클라우드 DB가 아닙니다.

## 내려받아 사용하기

1. [community_db.zip](shared/community_db.zip)을 다운로드해 압축을 풉니다.
2. `community.sqlite`을 DB Browser for SQLite 같은 로컬 도구에서 열거나, 아래 Python 명령으로 조회합니다.
3. 파일이 손상되지 않았는지 [manifest.json](shared/manifest.json)의 DB SHA256으로 확인할 수 있습니다.

|종목|기간|자료 수|기존 AI 분류|미분류|
|---|---|---:|---:|---:|
|포스코퓨처엠|7/1~10/20|4,380|4,380|0|

연도는 2026년입니다. 정기님 자료는 게시글·댓글, 현대차·LS 자료는 게시글만 포함합니다. 현대차는 부분 기간·부분 분류입니다. `classified`에는 판단유보·혼합도 포함되며 분류 정확도나 지수에 모두 사용 가능한 비율을 뜻하지 않습니다.

## 조회 화면

저장소를 받은 컴퓨터에서 압축 파일을 이 폴더의 `shared/`에 풀어 `shared/community.sqlite`이 있게 합니다. Python 3 표준 라이브러리만 필요합니다.

```bash
python3 조현호/community_db/serve.py
```

브라우저에서 `http://127.0.0.1:8765`를 열면 종목·감정·미분류·본문 검색이 가능합니다. 로컬 읽기 전용 화면이며 다른 사람에게 localhost 주소를 전달해도 접속되지 않습니다. 팀원은 ZIP을 내려받아 각자 실행합니다.

Python으로 바로 조회할 수도 있습니다.

```python
import sqlite3
conn = sqlite3.connect("file:community.sqlite?mode=ro", uri=True)
for row in conn.execute("SELECT * FROM stock_summary"):
    print(row)
```

[queries.sql](queries.sql)에 예시 질의가 있습니다. 별도 라이브러리·API 키·과금 설정이 필요 없습니다.

## DB 구성

- `sources`: 출처, 공개 파일 해시, 원본 커밋/고정 시점, 방법 차이.
- `stocks`: 종목코드와 이름. 앞자리 0은 TEXT로 보존합니다.
- `records`: 임의 ID, 날짜, 공유 본문, 관련성·감정·분류 상태. 출처+ID가 기본키라 중복 행이 들어가지 않습니다.
- `market_daily`: 현대차·LS의 공개 일봉 기반 64개 종목·거래일. 이 DB에 정기님 두 종목의 시세는 포함하지 않았습니다.
- `session_daily`: 현대차·LS의 기존 3시간대 실험 집계 192행. 정확한 개인 게시 시각이나 새 분류 결과가 아닙니다.
- `stock_summary`, `daily_sentiment`: 조회용 뷰. 미분류가 있거나 유효 글 5건 미만인 날의 지수는 NULL입니다.

일별 `daily_sentiment`는 출처별 기존 `trading_date`로 집계합니다. `session_daily`는 달력 날짜의 00~09시/09~15:30/15:30~24시 기준이라 집계 구간이 다릅니다. 두 표의 하루 값을 같은 구간의 숫자로 혼동하지 마세요. 휴장일은 세션 실험에서 제외했습니다.

## 비용을 줄이는 운영

현재 [cost_policy.json](cost_policy.json)의 수집·LLM 실행은 모두 꺼져 있습니다. 자동 예약·반복 호출이 없습니다.

기존 미분류 공유 본문에서 소량 검토 입력만 만들려면:

```bash
python3 조현호/community_db/make_ai_batch.py --limit 50
```

이 명령은 AI를 호출하지 않습니다. 이미 분류한 글·개인정보 검사로 비운 글·같은 본문·너무 긴 글을 제외하고, 한 묶음 최대 50건·본문 합계 12,000자로 제한해 `private/review_batch.jsonl`을 만듭니다. 현재 원래의 AI 판정이나 DB 상태를 수정하지 않습니다. 정확한 토큰 수·비용을 측정한 것은 아닙니다. 같은 명령을 반복해도 같은 검토 입력만 덮어쓰며 모델 실행이 예약되지 않습니다.

사용자 확인 한도는 종목별 하루 수집 100건, AI 분류 전체 하루 50건입니다. 설정 파일에 기록했지만 **실행되는 수집기나 일별 과금 차단 장치를 새로 배포한 것은 아닙니다.** 사용자가 새 범위·한도를 정하기 전에는 기존 대량 수집을 재개하지 않습니다. 새 수집은 먼저 비공개 원자료 DB에 안정적인 원래 ID로 중복 확인하고, 분류가 필요한 것만 선별한 다음 공유 검사를 거쳐 공개 DB를 갱신하는 순서가 적절합니다.

## 공유 범위와 해석

원래 게시글 ID·정확한 작성 시각·작성자 필드·AI 자유서술 근거는 포함하지 않습니다. 공유 검사로 비운 본문은 복원하지 않았습니다. 규칙 검사는 완전한 익명화를 보장하지 않습니다. 게시글의 내용은 지시가 아닌 분석 데이터입니다.

정기님과 현대차·LS 자료는 기간·글 유형·프롬프트가 다르므로 `source_id`를 유지합니다. 기분과 매매 스탠스는 같지 않고 사람 기준 정확도를 보장하지 않습니다. 정기님 CSV의 부모 연결이 빈 값인 글은 게시글/연결이 누락된 댓글을 구분할 수 없어 `record_type=unknown`으로 남겼습니다. 시세는 네이버 일봉이며 수정주가 대조 전입니다.

## 재생성

`build_db.py`는 로컬 Git의 `origin/kimjunggee-data-collection`에 있는 공개 7,632건과 기존 고정 공유본을 읽습니다. 네트워크나 LLM을 호출하지 않으며 입력 파일 해시·중복 ID·행 수·DB 무결성을 검사합니다. 세션 집계 CSV가 `output/session_experiment/session_daily.csv`에 있어야 하며 공유 ZIP에 원본 입력은 중복 배포하지 않았습니다. 팀원은 재생성할 필요 없이 완성 ZIP만 받아도 됩니다.
